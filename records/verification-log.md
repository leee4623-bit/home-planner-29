   - 무엇: 데스크톱용 위치(오른쪽 아래 400px 고정)가 375px 화면에서도 적용되어 패널 왼쪽이 화면 밖으로 나갔다.

   - 어떻게 고침: 넓은 화면(961px 이상)에서만 오른쪽 아래 고정, 좁은 화면은 하단 전체 폭.

25. **'개발용 문구 노출' 검사를 정적 패턴으로 만들었다가 오탐**
   - 무엇: 소스 코드의 문자열에서 `undefined`를 찾는 방식은 `typeof globalThis !== 'undefined'` 같은 정상 코드까지 잡았다.

## 2026-11-09 / 사례 보고서 가상 고객 재현

26. **팀원 엔진이 보고서 설계를 표현하지 못함**
   - 무엇: 연금 월 납입, 원금균등 상환, 실효 월이율((1+r)^(1/12)), 은행 적금의 납입분별 단리 이자, 계획별 초기 자산 재배치가 없어 보고서 수치(4,166.4 / 4,240.15 / 4,216.56)가 나오지 않았다.
   - 어떻게 발견: 보고서 입력을 엔진에 넣어 표 10·19와 월별로 대조.
   - 어떻게 고침: 다섯 기능을 엔진 옵션으로 추가하고 보고서 수치를 R1~R11 정답 테스트로 고정. 기존 A·B 기대값은 바꾸지 않고 이전 시연 자료로 계속 검사.

27. **명세의 테스트 명령이 Node 22에서 실패**
   - 무엇: `node --test tests/`는 Node 22 이상에서 폴더를 파일로 해석해 실패한다.
   - 어떻게 고침: `node --test tests/*.test.js`로 명세·README를 고침.

28. **은행 상품만 있는 계획에서 정책 도구 화면이 비어 보임**
   - 무엇: 정책상품을 빼고 은행 적금을 넣자 화면 렌더 테스트가 '빈 화면'으로 잡았다.
   - 어떻게 고침: 정책상품이 없을 때는 정책 비교 대신 이유(보고서 9장)와 은행 상품 비교 표를 보여 줌.

29. **계산 조건별 결과 표가 휴대폰에서 깨짐**
   - 무엇: 6열 표에 HTML 문자열을 그대로 넣어 `<span class="num">`이 글자로 보였고, 조건 칸이 한 글자씩 줄바꿈됐다.
   - 어떻게 발견: 375px 화면 스크린샷.
   - 어떻게 고침: 줄 목록 형태로 바꾸고 숫자를 HTML로 그림.

30. **고객 정보 저장 시 원금균등 정보가 사라질 위험**
   - 무엇: 부채 입력 폼에는 상환 방식·월 원금 칸이 없어 저장하면 원리금균등으로 되돌아갈 수 있었다.
   - 어떻게 고침: 같은 이름의 기존 부채에서 화면에 없는 필드를 이어받도록 함. 설계사 정보 화면에 상환 방식 열 추가.

## 2026-11-09 / 첫 화면·그래프

31. **입력 전에 버튼을 누르면 오류**
   - 무엇: 상태가 없는 첫 화면에서 '입력 완료'를 누르면 화면 공통 계산(derive)이 상태를 찾다가 멈췄다.
   - 어떻게 발견: 브라우저 자동 점검(빈 양식 제출).
   - 어떻게 고침: 상태가 없을 때는 계산 없이 화면 정보만 넘기도록 함.

32. **막대 그래프의 목표 글자가 막대 값과 겹침**
   - 무엇: 설계 후 막대(4,216.6)와 목표선 글자(목표 4,150)가 겹쳤다.
   - 어떻게 발견: 390px 스크린샷.
   - 어떻게 고침: 막대 그래프의 목표 글자는 범례에만 둔다. 이후 모든 그래프의 글자 상자 겹침을 자동으로 검사.

33. **'일부 항목만 기록' 오표시**
