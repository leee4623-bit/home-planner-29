> **시연판(서버 없음) 바로 열기:** https://leee4623-bit.github.io/home-planner-29/ — 비밀번호 `1234`
> 시연판은 브라우저 안에서만 동작합니다. 데이터가 그 기기에만 저장되고 **다른 기기·설계사와 동기화되지 않습니다.**
> 고객–설계사 실시간 동기화는 **서버판**(내 PC 실행 또는 Render 배포)에서만 동작합니다.

설계사가 재무계획을 세우고, 고객이 매월 실행 상황을 확인하는 재무설계 서비스입니다.
목표는 32세까지 기존 부채를 갚고 **신규 대출 없이** 이사자금을 마련하는 것입니다. 시연 모드의 고객과 금액은 모두 **공모전용 가상 사례**입니다.

## 가장 쉬운 실행 방법(내 PC)

1. Node.js LTS를 한 번 설치합니다(https://nodejs.org).
2. 압축을 푼 폴더에서 **`시작하기.bat`**(윈도우) 또는 **`시작하기(맥).command`**(맥)를 더블클릭합니다.
3. 브라우저에 http://localhost:8080 이 열립니다. 검은 창은 앱을 쓰는 동안 닫지 마세요.
   같은 PC의 다른 브라우저(또는 시크릿 창)로 고객·설계사에 각각 로그인하면 실시간 동기화를 확인할 수 있습니다.

## 실행 (명령어로)

Node.js 22.5 이상. 외부 패키지가 없어 `npm install`이 필요 없습니다. `DATABASE_URL`이 없으면 내 PC 파일 DB(SQLite), 있으면 공용 Postgres를 씁니다.


시연 모드(기본)에서는 빈 DB에 아래 가상 계정이 만들어집니다(비밀번호 `FP_DEMO_PASSWORD`, 기본 `1234`).

3. **미배정 설계사 버튼 제거** — 배정 고객이 없으면 ‘현재 배정된 고객이 없습니다’.
4. **고객–설계사 실시간 동기화** — 아래 ‘배포 구조’ 참고.

## 배포 구조와 선택 이유

**구성: Node.js 서버(Render 웹 서비스 1개) + Neon PostgreSQL + SSE 실시간.** 화면(PWA)도 같은 서버가 제공합니다.

- 화면과 API가 같은 주소라 로그인 쿠키(HttpOnly·SameSite=Strict)와 실시간 연결이 추가 설정 없이 동작하고, 모바일 웹·설치형 앱(PWA)이 모두 같은 서버를 씁니다.
- Render 무료 서버는 재시작·재배포·휴면 때 디스크가 지워지므로 모든 공통 데이터는 Neon에 저장합니다. 브라우저 localStorage는 공통 데이터 저장에 쓰지 않습니다(시연판만 예외).
- **SSE를 고른 이유:** 이 앱의 실시간은 "서버 → 화면" 방향 알림이 대부분이고, 저장은 이미 일반 요청(PATCH/POST)으로 버전 확인을 거칩니다. SSE는 일반 HTTP 위에서 동작해 같은 로그인 쿠키·권한 검사를 그대로 쓰고, 브라우저가 끊기면 자동으로 다시 연결하며 마지막 번호(Last-Event-ID)부터 놓친 변경을 받습니다. 외부 패키지 없이 구현할 수 있어 기존 구조(의존성 0개)와 충돌하지 않습니다. 양방향 실시간 대화가 필요해지면 WebSocket으로 바꿀 수 있습니다.
- 기존 기술과 충돌한 점: npm 패키지(pg 등)를 쓰지 않는 구조라 Postgres 연결을 직접 구현했습니다(`server/pg.js`, SCRAM 인증·TLS 지원). 내 PC 실행은 계속 SQLite 파일을 씁니다(`DATABASE_URL`이 없을 때).

### 데이터베이스 구조(주요 표)
| 표 | 내용 |
|---|---|
| users / sessions | 고객·설계사 계정(역할, scrypt 비밀번호 해시, 시연 여부, 사용 중지), 로그인 세션(토큰의 HMAC만 저장) |
| clients / assignments | 고객 프로필, 설계사↔고객 담당 배정 |
| client_data | 고객이 한 페이지에서 입력한 소득·지출·자산·부채·주거목표·목표 시점(버전·항목별 버전) |
| risk_profiles | 위험성향(금융기관 결과, 앱 설문 결과) |
| plans / baselines / plan_offers | 재무설계안(계산에 쓴 가정 전체를 버전별 보관), 실행 기준 이력, 설계사 제시·고객 선택 |
| strategy_sets / revisions | A/B/C안, 실적 반영 조정안(제안으로 저장, 고객 확인 전 확정 계획 불변) |
| records / month_closures / scheduled / transactions | 월별 실제 입력값, 월 확정, 예정 결제, 거래내역 |
| notifications / push_subs / notif_settings | 앱 내 알림, 푸시 구독, 알림 설정 |
| changes / audit / idem | 변경 이력(변경자·시각·항목·데이터 버전), 감사 기록, 중복 요청 방지 |
| app_meta / schema_migrations | 푸시 서명 키 등 서버 설정, 적용한 마이그레이션 |

스키마 파일: `migrations/001_init.sql`. 적용: 서버가 시작할 때 아직 적용하지 않은 파일을 자동 적용하고, 직접 하려면 `DATABASE_URL`을 환경변수로 지정한 뒤 `npm run migrate`. 이미 적용한 파일은 다시 실행하지 않으며 데이터를 지우지 않습니다.

### 알림: 앱 내 알림과 푸시 알림은 따로입니다
- **앱 내 알림(구현):** 비상금 부족, 목표 예상액 부족, 계획 대비 지출 초과, 납입 부족, 새 제안·조정안. 앱을 열면 ‘알림’ 화면과 실시간 표시로 보입니다.
- **푸시 알림(구현, 실제 휴대폰 미검증):** 앱이 닫혀 있을 때 Web Push로 보냅니다. 고객이 ‘알림’ 화면에서 켜야 하고, 아이폰은 홈 화면에 설치한 앱에서만 됩니다. **Render 무료 서버가 잠든 동안에는 정기 점검과 푸시가 보내지지 않습니다.**

## 배포하기(초보자용 순서)

비밀번호·연결 문자열은 **채팅이나 코드에 붙여 넣지 말고**, 아래 각 서비스의 설정 화면에 직접 입력하세요.

### 1) Neon에서 데이터베이스 만들기
1. https://neon.com 접속 → **Sign up**(GitHub 계정으로 가입 가능).
2. **Create project**: Project name `home-planner`, Postgres 버전은 기본값, Region은 **AWS Asia Pacific (Singapore)** 등 가까운 곳 → Create.
3. 프로젝트 화면의 **Connect** 버튼 → Connection string에서 **Pooled connection은 끄고**(직접 연결) 표시된 `postgresql://…?sslmode=require` 문자열을 **복사만** 해 둡니다(어디에도 붙여 넣지 말고 2)에서 바로 사용).

### 2) Render에 서버 만들기
1. https://render.com → **Get Started** → GitHub로 가입·로그인 → GitHub 권한 요청에서 `home-planner-29` 저장소 접근 허용.
2. 대시보드 **New + → Blueprint** → 저장소 `leee4623-bit/home-planner-29` 선택 → Blueprint 이름 입력.
3. 값 입력 화면이 나오면:
   - `DATABASE_URL`: 1)에서 복사한 Neon 문자열 붙여 넣기
   - `FP_DEMO_PASSWORD`: 시연 계정 비밀번호(공개 주소이므로 1234 말고 새 값 권장)
   - `FSS_API_KEY`: 없으면 비워 둠
   - `SESSION_SECRET`, `FP_ADMIN_TOKEN`은 Render가 자동으로 만듭니다.
4. **Apply / Deploy** → 몇 분 뒤 `https://home-planner-29.onrender.com` 같은 주소가 생깁니다(이름이 겹치면 뒤에 글자가 붙음).
5. 값을 나중에 바꾸려면: 서비스 → **Environment** → 수정 → Save(자동 재배포).

### 3) 실제 계정 만들기(시연 계정과 분리)
- 시연 모드(`FP_DEMO=1`)의 `@demo.kr` 계정은 시연 비밀번호를 쓰는 **가상 계정**이고, `FP_DEMO=0`으로 바꾸면 로그인이 막힙니다.
- 실제 계정은 **`https://(내 주소)/admin.html`** 에서 만듭니다: Render → 서비스 → Environment에서 `FP_ADMIN_TOKEN` 값을 확인(눈 모양 버튼)해 그 화면에 붙여 넣고 → 계정 만들기(8자 이상 비밀번호) → 담당 배정. 무료 서버에는 Render Shell이 없어서 이 화면(또는 같은 기능의 `/api/admin/*`)을 씁니다.
- 실제 운영으로 전환: Environment에서 `FP_DEMO`를 `0`으로 저장.

### 4) 배포 후 확인
1. `https://(내 주소)/api/health` → `{"ok":true,"db":"postgres",…}`.
2. PC 브라우저에서 설계사, 휴대폰에서 고객으로 로그인 → 위쪽 상태 ‘실시간 연결됨’.
3. 고객이 ‘내 정보·실적 입력’에서 값 저장 → 설계사 화면에 ‘고객 정보가 업데이트되었습니다’.
4. 설계사가 새 안을 저장·‘고객에게 제시’ → 고객 화면 알림 → 선택 전 실행 기준 그대로, 선택 후 변경.
5. 휴대폰 비행기 모드 → 해제 후 그 사이 변경이 나타나는지.
6. Render → **Manual Deploy → Restart service** 후 다시 로그인해 값이 남아 있는지.

## 무료 요금제 제한(2026-11-04 공식 문서 확인)

**Render 무료 웹 서비스** ([공식 문서](https://render.com/docs/free), [요금](https://render.com/pricing.md))
- 15분 동안 들어오는 요청이 없으면 잠들고, 다음 접속 때 깨어나는 데 약 1분 걸립니다. 열어 둔 실시간(SSE) 연결만으로는 깨어 있지 않습니다.
- 작업공간당 월 750시간 무료(잠든 시간은 제외). 초과하면 그달 남은 기간 정지.
- 디스크는 재배포·재시작·휴면 때 지워짐(그래서 데이터는 Neon에 저장). Shell 접속 없음. 언제든 재시작될 수 있음.
- Hobby 작업공간 무료 전송량 월 5GB, 결제수단이 없으면 초과 시 그달 정지.

**Neon 무료** ([공식 문서](https://neon.com/docs/introduction/plans))
- 프로젝트당 저장 1GB, 컴퓨트 월 100 CU-시간, 5분간 사용이 없으면 일시 중지(다음 요청 때 자동 재개, 끌 수 없음).
- 복원 가능 기간(instant restore) 최대 6시간. 한도를 넘으면 컴퓨트가 정지되거나 쓰기가 실패하지만 **데이터가 지워지지는 않습니다.**

**항상 바로 응답하게 하려면(유료, 결제는 직접 확인 후 진행)**
- Render 웹 서비스 유료 인스턴스(512MB, 1 CPU 미만): **월 7달러**. Hobby 작업공간 요금은 0달러.
- Neon은 이 앱 규모(수백 MB 미만)면 무료로 충분합니다. 7일 복원·중지 끄기가 필요하면 Launch(사용량 과금: 컴퓨트 0.106달러/CU-시간, 저장 0.35달러/GB-월).
- 예상: Render 월 7달러 + Neon 0달러 → 약 **월 7달러(약 1만 원)**. 금액은 바뀔 수 있으니 결제 전에 각 요금 페이지를 다시 확인하세요.

## 백업과 복구
- **Neon 자체 복원:** Neon 콘솔 → 프로젝트 → **Restore**에서 최근 6시간(무료) 안의 시점으로 되돌릴 수 있습니다. 실수 직후에만 쓸 수 있으니 정기 백업을 따로 받으세요.
- **파일 백업(권장, 주 1회):** 내 PC에서 실행 창을 열고, 연결 문자열을 **그 창의 환경변수로만** 지정한 뒤 실행합니다.
  - 윈도우 PowerShell: `$env:DATABASE_URL = Read-Host "Neon 연결 문자열"` (붙여 넣어도 화면·기록에 남지 않게 입력) → `npm run backup -- export backup-2026-11-04.json`
  - 맥: `read -s DATABASE_URL; export DATABASE_URL` → `npm run backup -- export backup-2026-11-04.json`
  - 백업 파일에는 고객 금융정보와 비밀번호 해시가 들어 있으니 GitHub에 올리지 말고 안전한 곳에 보관하세요(`.gitignore`가 `backup-*.json`을 제외).
- **복구:** Neon에 새 프로젝트(빈 DB)를 만들고 그 연결 문자열로 `npm run backup -- restore backup-….json`. **계정이 하나라도 있는 DB에는 복구하지 않습니다**(기존 데이터 보호). 복구 후 Render의 `DATABASE_URL`을 새 DB로 바꿉니다.
- `pg_dump`를 쓸 줄 안다면 `pg_dump "$DATABASE_URL" > backup.sql`도 가능합니다.

## 안드로이드 폰을 서버로 쓰기(Termux)

PC 없이 안드로이드 폰 한 대가 서버가 되고, 다른 폰(아이폰 포함)·PC는 그 폰에 접속합니다. 아이폰은 서버로 쓸 수 없고 접속하는 쪽으로만 씁니다.

1. 서버 폰에 **Termux**를 설치합니다(F-Droid 또는 GitHub 배포판 권장 — Play 스토어판은 오래되어 패키지 설치가 안 될 수 있음).
2. Termux에서 한 줄 실행(처음 한 번):
   ```
   curl -fsSL https://raw.githubusercontent.com/leee4623-bit/home-planner-29/main/termux/setup.sh | bash
   ```
3. 서버 켜기: `fp-start` → 화면에 주소가 나옵니다.
   - 이 폰: `http://localhost:8080` (크롬에서 ‘앱 설치’ 가능)
   - 같은 와이파이의 다른 기기: `http://192.168.x.x:8080`
   - 어디서나: `https://○○○.trycloudflare.com` ← 아이폰·다른 폰에서 열고 ‘홈 화면에 추가’
4. 끄기: Termux에서 Ctrl+C. 데이터는 `~/fp-data/planner.db`에 남아 다음에 켜도 그대로입니다.

주의
- Termux가 켜져 있는 동안만 접속됩니다. 화면이 꺼져도 돌도록 `termux-wake-lock`을 걸지만, 휴대폰 절전 설정에서 Termux를 ‘배터리 최적화 제외’로 바꿔 두세요.
- trycloudflare 주소는 켤 때마다 바뀝니다. 바뀌면 접속하는 폰에서 새 주소로 다시 열어야 합니다. 고정 주소가 필요하면 Render 배포를 쓰세요.
- 서버 폰을 잃어버리거나 초기화하면 데이터도 사라집니다. 중요한 데이터는 `~/fp-data` 폴더를 따로 복사해 두세요.
- 앱을 새 버전으로 바꾸려면 `setup.sh` 한 줄을 다시 실행합니다(데이터는 유지).

## 휴대폰 설치(PWA) — 참고

PWA 설치와 Secure 쿠키에는 **https 주소**가 필요합니다. 이번 버전은 서버가 있으므로 Netlify Drop 같은 정적 호스팅에는 올릴 수 없습니다. Node 서버와 **영구 디스크**를 지원하는 곳에 배포하세요(예: Render, Fly.io, Railway).

배포 설정:
- 시작 명령: `npm start`
- `NODE_ENV=production`
- `FP_DB`를 영구 디스크 경로로 지정(예: `/data/planner.db`)

배포 후 휴대폰에서 주소를 열고 **앱 설치** 버튼의 안내를 따르면 됩니다.
- 아이폰: 사파리 → 공유 → 홈 화면에 추가
- 안드로이드·데스크톱: 크롬 설치 메뉴

서비스 워커는 앱 화면 파일만 저장합니다. 개인 재무 데이터(`/api`)는 기기에 저장하지 않습니다.

**설계사**

- **자금 경로**: 설계 전 예상, 설계 후 예상, 실제 실행, 최근 추세 지속, 목표금액을 한 그래프에 그립니다. 상환 완료·비상금 확보·만기·보증금 반환·이사 시점도 표시합니다.
- **충격 시나리오**: 소득 감소, 실직, 생활비 상승, 목표 보증금 상승, 투자 손실, 보증금 반환 지연을 동시에 적용할 수 있습니다. 각 충격의 시작·기간·규모는 수정할 수 있습니다.
- **생활비 역산**: 월별 계산을 반복 실행해 목표 시점을 지키는 데 필요한 최소 절감액을 찾습니다. 시작월과 최소 필수생활비를 정할 수 있고, 절감만으로 불가능하면 대안을 보여줍니다. 결과를 적용하면 새 수정안으로 저장됩니다.
- **정책·상품**: 청년미래적금, 중기 재직자 우대저축공제, 중기 취업 청년 소득세 감면, 청년전용 버팀목전세자금을 비교합니다. 조건마다 출처·확인일·확인 상태를 표시합니다. 대출 활용은 무대출 기본안과 분리한 비교안으로만 보여줍니다.
- **소득 가정**: 인상률 0·1·2%·사용자 지정, 승진 인상, 초과소득 배분 규칙, 소득 근거, 민감도를 다룹니다.
- **계획 버전**: 기존 계획을 덮어쓰지 않고 새 버전으로 저장합니다.
- **실행 기록**: 고객 실행 현황과 경보를 조회만 할 수 있습니다.
- **계산 검증**: 월별 계산표와 CSV 내려받기를 제공합니다.

**고객**
- **이번 달**: 계획·실제·차이, 누적 차이, 두 가지 예측(계획대로 / 최근 추세 지속)을 보여줍니다. 실제 기록과 가정해보기는 분리되어 있어, 가정해보기 값은 저장되지 않습니다.

## v2.1 기능

### 위험성향 확인 (챗봇형 설문)
- 고객의 '성향·설계안' 탭에서 진행합니다. 기존 결과가 있으면 먼저 보여 줍니다. 금융기관 공식 결과와 앱 자체 설문 결과는 따로 저장합니다.
- 소득·부채·목적이 바뀌었거나 결과가 없으면 앱 자체 설문을 권합니다. 나이나 소득만으로 성향을 추정하지 않습니다.
- 10문항을 한 번에 하나씩 묻습니다. 선택지마다 '잘 모르겠음'이 있고, 진행률 표시·이전 문항·답변 수정이 됩니다. 자유 질문은 설명용이며 점수에 반영하지 않습니다.
- 배점·가중치·유형 구간·제한 규칙은 `public/js/data/riskConfig.js`에 있습니다. **앱 자체 참고용 기준**(APP-RISK-2026.11-v1)이며, 금융기관의 공식 적합성 판단을 대신하지 않습니다.
- 손실 감수 의향이 재무 여력보다 30점 넘게 높거나 답변끼리 모순되면 '추가 확인 필요'로 표시합니다. 이사에 꼭 필요한 주거 핵심자금은 유형과 관계없이 원금 보전형으로만 운용합니다.

### A/B/C 재무설계안
- 설계사가 '성향·A/B/C' 탭에서 만들고, 조정값을 바꿔 보며 검토한 뒤 고객에게 제시합니다.
- 고객이 한 가지를 선택하면 새 계획 버전으로 저장되고 실행 기준 계획이 됩니다.
- A안은 안정성과 상환 우선, B안은 저축과 생활의 균형, C안은 목표일 등 조건을 조정하는 전략입니다. 세 안 모두 같은 초기 조건으로 계산합니다.
- 투자 비율은 0%로 두고 기대수익률도 올리지 않습니다. 달성 확률은 표시하지 않고, 대신 불리한 상황(소득 감소·생활비 상승·투자 하락)에서의 결과를 보여 줍니다.

### 월별 지출·재계산·수정안
- 월중에는 확정 지출에 미확인 거래와 예정 결제를 더해 '잠정 결과'로 보여 줍니다.
- 고객이 월을 확정하거나, 월이 끝나고 유예기간(기본 3일)이 지나면 '확정 결과'가 됩니다. 확정된 달의 지출만 계산에 반영합니다.
- 계획보다 많이 쓰면 남은 기간에 나눠 보완하는 수정안을 만듭니다. 필수생활비 하한은 지키고, 생활비 절감만으로 부족하면 목표일·목표금액·추가 소득 대안을 보여 줍니다.
- 계획보다 적게 쓰면 고객이 통장 잔액을 확인한 뒤에만 '비상금 → 부채 → 주거' 순서로 한 번 배분하는 수정안을 만듭니다.
- 수정안은 고객이 확인해야 적용됩니다. '자동 적용'에 동의하면 정해 둔 월 한도와 필수생활비 하한 안에서 생활비 예산만 자동으로 바뀝니다. 목표일 변경·신규 대출·위험 확대·상품 해지는 자동으로 적용하지 않습니다.
- 앱 안의 계획만 바뀌며, 실제 계좌이체나 자동이체는 바뀌지 않습니다.

### 알림
- 서버가 1시간마다, 그리고 실적이 바뀔 때마다 점검합니다. 간격은 `FP_CHECK_MINUTES`로 바꿀 수 있습니다.
- 알림은 '발생 → 영향 → 제안' 순서로 쓰고, 같은 상황은 한 번만 알립니다. 알림 종류·방해금지 시간·수신 여부를 설정할 수 있습니다.
- Web Push: 고객이 '이 기기에서 알림 받기'를 눌렀을 때만 권한을 요청합니다. 키는 처음 실행할 때 `data/vapid.json`에 생성됩니다.
- 잠금 화면에는 기본적으로 금액 없이 "새 알림이 있습니다"만 표시합니다. 푸시를 지원하지 않거나 거부하면 앱을 열 때 알림함에 보입니다.
- 앱을 닫은 상태에서 받으려면 서버(검은 창)가 켜져 있어야 합니다.

### 화면
- 전체 배경은 흰색으로 고정했습니다. 기기가 어두운 모드여도 흰 배경으로 보입니다.

## 계좌 연동 범위
- 은행 아이디·비밀번호·인증서는 받지 않습니다.
- 실제 마이데이터·오픈뱅킹 연동은 허가받은 사업자와 계약한 뒤 붙여야 합니다. 이때 `server/linking/provider.js`의 `fetchTransactions` 규약을 구현하면 됩니다. 인증은 사업자의 동의 화면에서 이루어지고, 서버는 사업자가 발급한 토큰만 보관합니다.
- 지금은 CSV 가져오기와 시연용 가짜 거래만 지원합니다.

## 보안
- 비밀번호는 scrypt로 해시해 저장합니다.
- 세션은 HttpOnly·SameSite=Strict 쿠키로 관리하고, DB에는 토큰 해시만 저장합니다. 유효시간은 12시간입니다.
- 상태를 바꾸는 요청은 CSRF 방지 헤더가 있어야 처리합니다.
- 로그인 시도는 10분에 5회로 제한합니다.
- CSP를 비롯한 보안 헤더를 적용했습니다.
- 모든 고객 데이터 API는 서버에서 `canAccess`로 권한을 검사합니다. 고객은 자기 데이터만, 설계사는 배정된 고객만 볼 수 있습니다.
- 설계사는 실행 기록을 수정할 수 없고, 고객은 계획을 수정할 수 없습니다.
